① 模型结构：它到底是什么

一句话：它是一个视觉语言模型（VLM）在做「图像 → 文本」的生成式 OCR，跑在 HuggingFace transformers 上，不是传统的「检测 + 识别」两阶段流水线，也不是 llama.cpp 那种纯文本推理引擎。

三方对照

维度传统 OCR（Tesseract / PaddleOCR）llama.cppOCR2（Unlimited-OCR-2）
本质检测(文字框)+识别(CRNN)两阶段纯文本 GGUF 推理引擎多模态 VLM，自回归生成
输入图像文本 token图像
输出字符序列（无语义）文本 token文本（含 LaTeX 公式片段）
公式基本无解不涉及原生输出 \frac / ^ / $
加载方式轻量二进制GGUF + metal/cuda/rocblas 后端trust_remote_code=True 加载自定义模型代码
关键认知：Complexity 不在模型本身，而在「两头」——模型加载（含 A 卡 ROCm 坑）和外圈工程（方向检测、退化护栏、PDF 重建）。模型推理循环本身反而是直白的。

② 为何选 VLM 而非传统 OCR

核心 trade-off：用「慢」换「质量」。生成式逐 token 输出比两阶段识别慢一个量级，但换来三样传统 OCR 给不了的东西：

  • 公式原生输出：VLM 直接生成 LaTeX 片段（\frac、^、$）。B1 实测重建出的 PDF 用 pypdf 抽提，能读到 $\overrightarrow{EM}\cdot$ 这类公式——这是「公式也可检索」的根。
  • 版面与语义理解：VLM 把整页当作语义对象理解，对退化页、双栏、扫描噪点更鲁棒，不会像传统 OCR 那样把公式拆成乱码字符。
  • 可检索文本层质量：输出是自然语言 + 公式的混合文本层，标准 PDF 工具（pypdf）即可提取，不依赖私有格式。
代价：速度。早期单本冷启动实测 ≈91s/页（含模型冷加载）；B1 整批 2538 页 / 687.9 分钟 ≈16s/页（模型只加载一次，摊销后大幅下降）。若追求纯速度、且内容无公式，传统 OCR 仍更合适。

③ ROCm 坑（A 卡 + Windows）

RX 9060 XT
16GB 显存 · A 卡

Windows · 实测可用
shim
仅 A 卡+ROCm+Win 需要

实测环境：RX 9060 XT 16GB + Windows + ROCm 7.2.1。A 卡在 Windows 上跑 VLM 是大坑，集中在两点：

  • 设备枚举 / 分布式初始化：ROCm 在 Windows 上的进程组、device index 行为与 Linux 不同，直接跑会报 device 相关错误。infer/rocm_dist_shim.py 就是为此存在——它仅在「A 卡 + ROCm + Windows」组合下需要，作用是绕过这些初始化坑。N 卡（CUDA）或 Linux 下不需要。
  • 驱动 / 构建版本对齐：PyTorch 的 ROCm build 必须与系统 ROCm 大版本匹配，否则加载即崩。16GB 显存跑 3B 模型（batch=1 单页）绰绰有余。
迁移经验：同样一张卡，Linux + ROCm 比 Windows + ROCm 稳得多。Windows 下 shim 是必要的；若上 Linux，shim 通常可省。

④ 护栏链设计（为什么「复杂」不只在两头）

让 OCR2 能跑完 2538 页而不被坏页拖垮，靠的是五道护栏，缺任何一道都会让一页吃掉整轮：

各护栏的实测参数

护栏机制实测阈值 / 数据
方向检测 OSD-l osd 显式调用；结果写在 <base>.osd 文件（不在 stdout）；大图先降采样到 1024 再测漏写 -l osd 默认 chi_sim 不做方向检测 → 整页颠倒

认知更新：旧判据「符号保真>0 ⇒ 原生文本层」已不适用——OCR2 以 LaTeX 输出公式，不落 MATH_SYM 的 Unicode 符号，旧口径 symbol==0 → L1 会把公式产物误判成 L1。代理指标（字数）不足以判定方向正确性，必须落到最终判据（公式/术语/退化度）复核。

⑤ 怎么迁移到别的卡

NVIDIA（CUDA）

  • 最干净：去掉 rocm_dist_shim.py，装 CUDA 版 PyTorch，--device cuda。
  • 无 shim、无 Windows ROCm 坑，跑起来基本零摩擦。

其他 A 卡 / Linux

  • Linux + ROCm 比 Windows 稳，shim 通常可省；若保留，需确认 shim 适配你的 ROCm 版本。
  • 不同 A 卡型号注意显存：3B 模型 batch=1 单页约数 GB，16GB 充裕，8GB 卡需降分辨率或 batch。

CPU fallback

  • 仅用于验证管线连通性，速度极慢（分钟级/页），不当生产用。

跨平台去硬编码（已落地在开源仓库）

  • 所有机器专属绝对路径（E:/uocr_models、E:/uocr_env、C:/Users/lg、C:/Windows/Fonts/simhei.ttf 等）改为 CLI 参数 / 环境变量 / 相对路径。
  • 跨平台字体探测 find_cjk_font()：枚举 Windows / Linux / macOS 常见中文字体路径，缺失时明确报错而非静默用错字体。
  • --model 改为必填，--tesseract 可配，去全局变量、改参数传递（修掉了 global TESSERACT 的 SyntaxError）。

# 3) 方向与退化（护栏不可省）
#    OSD 必须 -l osd，结果在 <base>.osd；退化阈值 0.5

# 4) 重建 PDF（CPU 活，不需 GPU）
python process/uocr_textlayer_pdf.py --json x.json --images ./pages --output x_可检索.pdf

python -c "from pypdf import PdfReader; print(len(PdfReader('x_可检索.pdf').pages))"
一句话收尾：Runtime 的复杂度 = 模型加载（A 卡 ROCm 坑）+ 外圈工程（五道护栏）+ 跨平台参数化。模型推理本身直白；难的是让它在 2538 页、各种退化扫描件上「跑得完、不丢页、可检索」。
